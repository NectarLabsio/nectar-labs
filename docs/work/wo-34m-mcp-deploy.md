# WO-34m — orchestrator — deploy through the Vercel and Railway connectors, no CLI login (Kunal, 2026-11-12: "use mcp for vercel and railway")
Supersedes the upload step of wo-34-deploy.md §Hosting (scripts/deploy/deploy-{vercel,railway}.sh stay as the CLI fallback). Everything else in WO-34 holds.

## Why a new path
- H-HOST asked Kunal for two CLI logins. He answered: use the connectors instead.
- The connectors cannot upload a local tree in practice:
  - Vercel `upload_file`/`create_deployment` take file bytes as tool arguments. The web set at fd06e11 is 235 files and 5.7 MB.
  - Railway `create-deployment` takes a GitHub repo only. Nothing is pushed to git.
  - Railway `get-bucket-credentials` returns no secret to an OAuth app (tool text), so no local S3 upload either.
- Path: a pinned source tarball moves through a private Railway bucket. Its bytes never pass through a tool argument.

## Pipeline (facts: wo-34r4; nothing below is built until its fact id exists)
1. **Railway project `nectar-labs`** (production env).
   - Bucket `artifacts`, private.
   - Function `artifacts`: Bun, one file, `scripts/deploy/artifacts-function.ts`.
     - Bucket keys come only as reference variables `${{artifacts-bucket.*}}`.
     - `ARTIFACT_TOKEN` is a random 32-byte deploy token.
     - Routes: `POST /presign {op: put|get, key}` → short-lived presigned URL (put 15 min, get 1 h). `GET /health`.
     - Keys must match `^src-[0-9a-f]{40}\.tar\.gz$` (one tarball per commit serves web, docs and Feed). Bearer token compared in constant time; otherwise 401. Sleep mode on.
2. **Tarball**: `scripts/deploy/make-artifact.sh <web|docs|feed> <commit>`.
   - `git archive` of the exact commit: root manifests, every workspace `package.json` (lockfile importers), and only the needed source paths.
   - web only: plus `apps/web/lib/generated/changelog.json`, generated by the repo's own script in a worktree of that commit with git present.
   - Writes the sha256 and uploads with a presigned PUT.
3. **Vercel** projects `nectar-labs-web` (rootDirectory `apps/web`) and `nectar-labs-docs` (rootDirectory `apps/docs-site`). `create_deployment` with inline files:
   - root `package.json`, `pnpm-workspace.yaml`, the app's `package.json`, `scripts/deploy/fetch-artifact.mjs` (Node; curl and sha256sum are not documented in the build image, F-425), and `.nectar-artifact` (`<name> <sha> <sha256>`).
   - installCommand `node ../../scripts/deploy/fetch-artifact.mjs <filter>` (cwd = rootDirectory, F-424): presigned URL from `.nectar-artifact` → download → sha256 check → extract → `pnpm@10.34.9 install --frozen-lockfile --filter <app>...`.
   - buildCommand: web `pnpm exec next build` (changelog pre-generated, same script, same commit); docs `pnpm build`.
   - No token at Vercel: `.nectar-artifact` carries a 1 h presigned GET. Env: the WO-34 deploy env list in docs/STATE.md.
4. **Railway service `feed`**: public image `node:22.22.2-bookworm`, volume `/data`.
   - Start command:
     - Fetch, verify and extract `feed-<sha>` into `/data/src/<sha>`, cached on the volume (restarts work after URLs expire).
     - `pnpm install --frozen-lockfile --prod --ignore-scripts --filter feed` (same as services/feed/Dockerfile).
     - `exec node --disable-warning=ExperimentalWarning src/main.ts` in services/feed.
   - Variables: the WO-34 Feed list, plus SRC_SHA, SRC_SHA256 and SRC_URL (presigned GET, 21 days; the source is cached on the volume after first boot). Exact command: scripts/deploy/railway-feed-start.cmd.
   - Healthcheck `/health` with a long first-boot timeout. Railway domain.
